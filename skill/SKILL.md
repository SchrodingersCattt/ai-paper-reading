# 读懂方法并核对适用范围

输入是一篇本地论文和一个具体阅读问题或后续用途。先解释论文实际做了什么，再判断哪些证据能用于回答读者的问题。只使用提供的论文和用户材料；原文事实、推断和待查内容分开写。

## 读论文

1. 检查文件页数、文本可读性和与问题相关的结果及方法页面。先确定读者要理解或使用的是什么；定位原文的图、表、方法与结果，并记录 PDF 页码。
2. 按实际研究顺序重建方法：每一步的输入、操作、输出及其作用。说明数据如何产生、什么量被模型学习、采用什么验证、最终进行了什么实验或模拟。不同步骤同名参数分别解释；论文未写的条件标为“未说明”。
3. 对支撑结论的数值记下指标、单位、对象、数据集及页码；区分实验值、计算值和预测值。任务限定只依据论文时，对原文未报告的数值标“未说明”；用户明确要求估算时再给计算过程和假设，并把推算与原文数值分开。判断时引用对应原文，不用摘要中的展望代替已经完成的工作。
4. 把目标用途拆成决定判断的条件，逐项对照实际数据、验证对象和实验或模拟条件。区分论文给出的事实与由这些事实作出的推断。涉及机器学习势时，读取 `references/ml-potentials.md`。
5. 材料足以核对时给出一个结论：`可用`、`部分可用`、`不可用`。关键条件与已展示结果相冲突时，明确指出冲突；目标中可独立使用的部分与仍需验证的部分分开解释。若缺少判断所必需的页面或无法读取，以 `材料不足停止` 结束，并写明缺什么、应去哪里查；缺失章节的页码无法从现有材料确定时，指出章节名称，不猜页码。材料完整但文中未报告某条件，不得把该条件写成已经满足。

## 交付

将结果以 UTF-8 写入 `answer.md`，包含以下标题：

1. `阅读问题`：论文身份、读者问题。
2. `方法链条`：用读者能理解的语言说明各环节和用途；关键事实标页码。
3. `证据与条件`：逐项写事实或推断、对应原文位置和关键数值的单位及来源。
4. `适用判断`：逐项比较目标与论文已完成内容，说明可用之处、冲突或未知。
5. `结论`：单独一行，使用上述四种结论之一。
6. `待查`：需补充的原文页、补充信息或验证；没有则写“无”。

运行同目录的 `check_answer.py` 检查 UTF-8 和结构。该脚本不核验论文事实；遇到无法可靠读取的页面，在结果中说明。
